# Data-integrity review: booking-hub plan (Phases 2-3 + cutover)

Read: plan (all), src/db/migrate.ts, src/db/leads.ts (claim + transaction). No DB opened.

## P0
1. **Cutover = two DBs, two pollers, one Gmail.** Railway and the Mac each have their own `leads.db`; `processed_emails` dedup is per file, so both will process and (once auto-send is on) both will reply to the same lead. Plan says "Railway is kept until the Mac proves itself" (Q4) AND "shut down after 0.5" (0.1) -- contradictory. **Change:** single-writer rule. Order: (a) set Railway `AUTO_SEND_ENABLED=false` + stop its poller, verify by log; (b) copy Railway DB to the Mac with `sqlite3 .backup` (not `cp` of a WAL DB), record row counts both sides; (c) start the Mac poller. Add a `runtime_lease` row (host, heartbeat) checked before every send; a second host refuses to send. Railway may stay up as a *read-only* fallback, never a poller.
2. **Send idempotency as written cannot work.** "Key on (lead, channel) checked before sending" cannot tell "crashed before send" from "sent, crashed before commit". Existing `claimLeadForSending` already leaves rows stuck in `sending`. **Change:** `outbound_messages` table: `idempotency_key UNIQUE` (lead/gig + kind + seq), `status intent|sent|unknown`, `provider_id`. Write intent in a transaction, send with a stable RFC822 `Message-ID` derived from the key, then record sent. On restart, an `intent` row is resolved by searching Gmail Sent for that Message-ID; Chrome/GigSalad sends with no lookup go to `unknown` = HOLD + alert, never auto-retry. Same table for reminders, contracts, invoices.
3. **Migrations.** Adding 7 tables + CHECK enums via initDb ALTERs repeats the pattern that needed a hand-rolled table rebuild, and that rebuild **silently DELETEs duplicate leads** (migrate.ts dedupe). **Change:** add a `schema_version` (PRAGMA user_version) runner: numbered SQL files, each in a transaction, automatic `.backup` to `data/backups/pre-vN.db` before applying, refuse to start if the version is newer than the code. Remove the silent-delete dedupe (fail loud instead). Keep status enums in lookup tables or app validation so a new state is not a table rebuild.

## P1
4. **Money model.** `gigs.total_cents` alone cannot express retainer, card fee, tips, refunds, overpayment, one payment for two gigs. `leads.actual_price` is REAL dollars. **Change:** `payments` (money received, `amount_cents INTEGER CHECK > 0`, rail, `source_ref`, `UNIQUE(rail, source_ref)`) + `payment_allocations(payment_id, gig_id, amount_cents, kind deposit|balance|tip|card_fee|cancellation)`; refunds are a negative allocation/row with `refund_of`, never an edit. Balance = total + fees - SUM(confirmed allocations excluding tips). Constraint: SUM(allocations) <= payment amount; overpayment shows as unallocated credit in the digest. Store `card_fee_cents` and `retainer_cents` at contract time (frozen), not recomputed.
5. **Match then reject.** `detected -> confirmed | rejected` has no undo. **Change:** add `reversed` (confirmed -> reversed, with reason, who, when); reversing cascades in one transaction: balance recomputed, gig status re-derived, pending "paid" reminders reinstated. Calendar event is NOT deleted automatically (alert Alex).
6. **Status state machine.** Linear list mixes contract and payment facts; no `cancelled`, no transition table. **Change:** keep `gigs.status` for lifecycle only (inquiry, quoted, contracted, confirmed, played, closed, lost, cancelled); derive paid state from allocations. Allowed transitions in one code map + `gig_events` audit log (from, to, actor alex|system, at). `cancelled` stores `cancelled_at`; if within 7 days of `event_date` (LA date math), `amount_owed = total`; otherwise retainer kept. System may only move inquiry->quoted and played (date passed); everything else needs Alex.
7. **Gig without a lead.** `lead_id` must be nullable with `origin direct|referral|text|backfill`; add `UNIQUE(lead_id) WHERE lead_id NOT NULL` so a lead cannot create two gigs. Backfill rows store `calendar_event_id UNIQUE` so a re-run cannot duplicate.
8. **Contacts dedup.** Match by normalized email (lowercase) and E.164 phone, `UNIQUE` partial indexes; GigSalad contacts have neither, so key them by `(platform, platform_user_id)`. Never auto-merge on name; propose merges to Alex.

## P2
9. **Timezone.** Store `event_date` as a local DATE ('YYYY-MM-DD', America/Los_Angeles) and `due_at` as UTC instant computed from a local time (e.g. 10:00 LA) via a tz library; never "now + 7*86400s". Test with gigs on Nov 8 and Mar 15 2027 (DST weeks). Store `event_tz` per gig for out-of-state gigs.
10. **Laptop backup.** Nightly `sqlite3 .backup` (or `VACUUM INTO`) to `~/Data` (encrypted store), keep 14, plus a restore test monthly against row counts. Time Machine copying a live WAL file is not a backup. Documents (signed PDFs) live outside the DB; back up `documents.path` targets too and store sha256.
11. **PII.** contacts, payments, signed contracts = client PII; plan has no retention or delete-on-request rule. Add one line: who can delete, what is kept for tax (7 yrs payments).

EARS to add: "two hosts running -> second refuses to send"; "payment reversed -> balance reopens"; "cancel at 6 days -> owed = total"; "reminder across DST fires at 10:00 local".
